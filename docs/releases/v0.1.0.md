# Tiangong v0.1.0 release notes

Tiangong v0.1.0 is the first public source release and introduces Reviewer v1 on the public AgentTeams/OpenClaw Worker boundary.

## Verified capability

Reviewer v1 performs Worker-local, static-only review of an explicit bounded list of UTF-8 workspace text files. Its exact tool surface is:

```text
start_work
extend_scope
read
check_completion
abandon_work
```

The runtime binds one active PracticeRun to the authenticated requester, permits append-only scope extension, records hash-chained machine state and Evidence, proves complete reads of specific file versions, and advances `done` only through a deterministic checkpoint and `run.completed` event.

The release gates include:

- 115 deterministic Worker tests;
- fixed image/profile/tool-surface checks;
- official Matrix → OpenClaw → Reviewer Basic completion;
- Recovery Full with later scope extension, remote journal durability, derived-snapshot deletion, Worker restart, and same-run journal reconstruction;
- the existing Matrix read/write approval, restart, exactly-once replay, payload-erasure, and cleanup regression;
- DCO, Gitleaks, repository policy, ShellCheck, dependency audit, clean-runner Worker tests, and image build in GitHub Actions;
- exact cleanup and a context-free Reader Test of the public design.

## Model-liveness observation

The declared qwen3.5-plus Journey canary safely remained active after rereading file A instead of the requested file B following restart. It created no valid B Evidence, checkpoint, completion, new run, or false `done`. Journey liveness is not an authorization, persistence, or recovery oracle and is not sampled until green.

Durable state recovery is a verified machine property. Subsequent model-driven progress depends on the configured gateway model; users may need a later turn when the model makes no progress.

## Explicit exclusions

Reviewer v1 does not:

- enumerate or review directories, glob patterns, repositories, git diffs, commits, branches, or pull requests;
- execute shell commands, tests, builds, linters, browsers, search, or external fetches;
- review binary, image, PDF, or Office content;
- edit, repair, or otherwise mutate workspace files;
- prove an immutable Candidate, test execution, semantic correctness, independent acceptance, or Team verification;
- support multiple simultaneous active runs, automatic task switching, or waiting-for-user workflows.

`done` means the static review workflow and machine checkpoint terminated. It does not imply `accept` or that the model's professional judgment is infallible.

## Deployment and security boundary

This release is intended for the documented local single-machine security model. A multi-user deployment requires a separate identity, TLS, storage, network, secret-management, and container-isolation design.

The repository publishes source only for v0.1.0. It does not publish npm packages or a prebuilt container image. The private runtime manifests remain version `0.0.0`; users build `tiangong-worker:dev` and `tiangong-worker-reviewer:dev` locally from the immutable base-image digest and locked public dependencies.

## Compatibility

This is the first public release. No migration or backward-compatibility path is required.
