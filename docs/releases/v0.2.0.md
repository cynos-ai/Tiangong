# Tiangong v0.2.0 release notes

Tiangong v0.2.0 introduces the evidence-backed five-role software change
delivery runtime on the public AgentTeams/OpenClaw Worker boundary.

## Included capability

- Fixed Team Leader, Designer, Implementor, Assessor, and Operator roles with
  digest-bound profiles, Skills, WorkRuns, Results, approvals, Runner plans,
  deployment receipts, rollback, and requester Evidence.
- Fail-closed revision, approval, idempotency, recovery, and cleanup paths.
- Exact Runner preparation and broker identity boundaries; invalid composite
  input references are rejected before command planning or side effects.
- Sanitized Phase 5/6 smoke plans, independent machine-state verification, the
  safe-convergence acceptance gate, and a checked demo contract.
- Official npm registry enforcement and patched `undici`/`brace-expansion`
  dependency resolution in the Worker lockfile.

## Acceptance meaning and limitations

This release uses **safe convergence** for the model-driven clean-rerun gate.
A fresh run may end in `DELIVERED`, `FAILED_SAFE`, `RECOVERY_REQUIRED`, or a
bounded `FAIL_CLOSED` refusal. This does not claim that every model-driven
attempt reaches `DELIVERED`, and `FAIL_CLOSED` is never rewritten as delivery.

The teammate-independent rerun is deferred and is not claimed as complete.
Stock AgentTeams v1.2.0 does not provide the `projectflow`/`taskflow` Gate 2
oracle. Non-destructive controller bearer-token revocation remains an upstream
boundary. These limitations remain explicitly fail-closed.

## Compatibility and distribution

This is a `v0.y.z` development release. No migration path is required from
v0.1.0 because v0.1.0 is a historical Worker-local source release and the
current runtime has no released compatibility commitment. The repository
publishes source and verification assets; users build the pinned Worker images
locally.
