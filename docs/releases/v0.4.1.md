# Tiangong v0.4.1 release notes

Tiangong v0.4.1 documents the verified boundary between the public
AgentTeams v1.2.2 infrastructure, the OpenClaw runtime, and Tiangong's
programmatic orchestration layer. It does not introduce a second model
runtime or restore the historical Tiangong Pi harness.

## Included verification

- A bare official AgentTeams v1.2.2 canary, using only the upstream Worker
  image, reached Running Workers and an Active Team.
- Leader and Member both accessed the same Team-scoped MinIO storage prefix,
  and a real Matrix message/reply roundtrip completed.
- The Tiangong orchestration canary completed Team creation, role/runtime
  injection, Leader admission/resume, Work/Task/Result coordination, Matrix
  handoff, fail-closed Implementor blocking, requester reporting, and exact
  cleanup with `deepseek-v4-flash`.
- The deterministic Phase C production-boundary suite passed, including the
  Worker, App, Coordination, injection, migration, and security contracts.
- The Linux Node 22 release checks passed the full Worker suite (375/375) and
  App suite (17 passed, 4 disposable-PostgreSQL cases intentionally skipped
  without an injected test database).

## Runtime boundary

- Leader, Designer, Assessor, and Operator use OpenClaw's built-in runtime.
- Implementor uses OpenClaw's official Codex app-server.
- Tiangong owns the CoordinationStore, Work/Task/Result/ToolResult contracts,
  Gates, Evidence, recovery state, and bounded control tools. It does not own
  a model loop, provider wire protocol, session runtime, or Pi harness.

## Known limitations

- The bare official Worker image does not expose the `taskflow`/`projectflow`
  MCP surface by default. The Tiangong control plugin and deployment-owned
  Coordination API remain required for authoritative task orchestration.
- AgentTeams v1.2.2 `agt`/REST still omits some Worker role, environment,
  Leader-session, and sidecar lifecycle fields. Production deployments must
  inject the reviewed bindings through the deployment layer.
- The full live Gate B driver keeps a conservative non-zero result for the
  intentionally blocked `RECOVERY_REQUIRED` terminal branch. The release does
  not reinterpret that branch as a green production execution path.
- Qwen, Alibaba Coding Plan, and Chat-only bridge routes remain optional
  canaries and are not part of the DeepSeek release matrix.

This is a `v0.y.z` development release. Credentials remain deployment-scoped
and are never stored in source, images, receipts, ToolResults, or logs.
