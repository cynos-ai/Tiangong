# Tiangong v0.3.1 release notes

Tiangong v0.3.1 is a patch release for the OpenClaw-first delivery path on
the public AgentTeams v1.2.2 boundary.

## Included fix

- Phase C role-injection contracts now follow the selected Codex model. The
  default remains `deepseek-v4-pro` for existing deterministic fixtures, while
  the production canary explicitly verifies `deepseek-v4-flash` without a
  false failure.

## Verification

- Real AgentTeams Gate B passed with Implementor `deepseek-v4-flash` and
  Leader `deepseek-chat`: native Responses, OpenClaw Codex app-server, role
  reinjection after Manager restart, Matrix Result/Requester reporting,
  Work/Task/ToolResult closure, and exact cleanup all passed.
- Deterministic Phase C, Worker, App, repository, shell, DCO, Gitleaks, and
  Worker package checks passed.

## Scope and limitations

The v0.3.0 scope remains unchanged: AgentTeams owns Team, Worker, Matrix,
storage, and WebUI lifecycle; Tiangong's deployment-owned adapter supplies
the role, Coordination, provider, consumer, and OpenCodex sidecar boundaries
that AgentTeams v1.2.2 does not expose through `agt`/REST.

Qwen Coding Plan remains a separate provider/catalog canary and is not claimed
as a green Team ToolResult path by this release.

This is a `v0.y.z` development release. Credentials remain deployment-scoped
and are never stored in source, images, receipts, ToolResults, or logs.
