# Tiangong v0.3.0 release notes

Tiangong v0.3.0 is the first release of the OpenClaw-first delivery path on
the public AgentTeams v1.2.2 boundary.

## Included capability

- Five fixed professional roles remain code-owned and fail-closed. Leader,
  Designer, Assessor, and Operator use the OpenClaw built-in runtime; the
  Implementor coding lane uses the Codex app-server route.
- AgentTeams Team/Worker/Matrix/WebUI integration is preserved. Tiangong's
  coordination API stores Work, Task, Result, and bounded ToolResult facts in
  PostgreSQL and exposes only scoped Worker control endpoints.
- Native Responses models use Codex directly. Chat-only models use the
  explicit OpenCodex bridge profile; no silent provider, model, wire-protocol,
  or runtime fallback is allowed.
- Codex capability detection is deployment-global and credential-free in its
  persisted record. OpenCodex sidecar provisioning, ready receipts, rotation,
  drain, recovery, and cleanup are deployment-owned and scoped to one Worker.
- Leader role inference accepts the authoritative AgentTeams
  `AGENTTEAMS_WORKER_ROLE=team_leader` identity. Fixed professional image
  stages materialize the non-Leader role IDs for the deployment adapter.

## Verification

- Worker package CI: **406/406** tests passed with zero production dependency
  audit findings.
- CI image build and Docker boundary checks passed, including disposable
  Runner isolation, uncertainty journaling, Runner broker identity,
  ToolResult retention, and deployment-service receipt checks.
- Real DeepSeek Codex success, OpenClaw/Codex coding A/B, Phase C sidecar
  lifecycle, restart/recovery, WebUI/Matrix visibility, and exact cleanup were
  verified on disposable resources.

## Acceptance meaning and limitations

This release is scoped to the DeepSeek-backed route and the deployment-owned
Phase C boundaries that are directly evidenced. It does not claim that
AgentTeams v1.2.2's embedded REST/`agt` path can inject arbitrary Worker
environment fields: production must use the reviewed deployment adapter for
role, Coordination, and sidecar receipt projection.

Qwen Coding Plan `qwen3.7-plus` remains a follow-up canary. Its direct upstream
endpoint is reachable, but the current local AgentTeams gateway provider
catalog rejects the model before a Team ToolResult turn. The Qwen canary is
therefore recorded as blocked-at-provider/catalog rather than green, and no
Qwen data migration or cutover is included in this release.

AgentTeams still owns Team, Worker, Matrix, storage, and WebUI lifecycle. It
does not currently ship an OpenCodex sidecar manager; that adapter remains an
explicit deployment component and can be replaced when AgentTeams exposes an
equivalent public lifecycle contract.

## Compatibility and distribution

This is a `v0.y.z` development release. No migration path is required from
v0.2.0 because the project has no external compatibility commitment yet.
Users build the pinned Worker and deployment-owned coordination/sidecar images
locally; credentials must be supplied through the deployment secret boundary.
