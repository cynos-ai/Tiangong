# Tiangong v0.5.0 release notes

Tiangong v0.5.0 records the product-foundation milestone: the six-agent
OpenClaw built-in delivery stack, the chat-first Matrix workbench, the
PostgreSQL product authority clean-cut, and the credential-isolated
AgentLoop diagnostic integration with verified cloud acceptance.

## Product foundation

- Six long-lived professional agents (Leader, Architect, Challenger,
  Developer, Reviewer, Tester) as AgentTeams Workers on OpenClaw
  built-in with `glm-5` as the initial default model. AgentTeams is the
  sole authority for providers, credentials, and Worker model state;
  member model mismatch fails closed.
- Portable product Skills (`work-coordination`, `work-planning`,
  `plan-challenge`, `test-driven-development`, `independent-code-review`,
  `scenario-testing`) preinstalled, version-locked, and bounded by
  `installed ∩ allowedSkills`. Skills grant no authority.
- A shared workspace tool contract locked to the pinned OpenClaw
  release (`read/write/edit/exec/process`), verified against the
  upstream plugin registry; only Developer local commits can enter the
  delivery chain.
- A real local delivery proof on an owned isolated project: Matrix
  request → WorkSpec → candidate Plan → Challenger approval → signed
  Developer commits → independent Reviewer and Tester results →
  CloseGuard completion, with machine-checked cleanup and a clean rerun.

## Chat-first workbench

- Deployment-owned Coordination runtime serves a three-pane workbench:
  full Matrix room conversation, Work history with nullable WorkSpec,
  plan refs and diffs, agent/model/Skill usage, tasks, results,
  tool-results, and deliverables.
- Human Web sessions are in-memory Matrix identities with HttpOnly
  cookies, CSRF protection, strict CSP, bounded history/sync, and
  session revocation. PostgreSQL never stores chat bodies.

## Product authority clean-cut

- PostgreSQL is the sole product runtime authority for Work, Task,
  Result, admission, replay, and wake state; the file-backed
  CoordinationStore is deleted.
- Inactive legacy runtimes are removed: Approval command, pending
  Operation, operation digest, native Runner, deployment/recovery,
  Codex/OpenCodex paths, fixed role profiles, TeamPlaybook, WorkRun,
  ResultEnvelope, and hash-chain evidence. External-write Operation and
  exact Human Approval return with real Adapters in a later stage.

## AgentLoop diagnostics

- Optional, disabled-by-default OpenTelemetry diagnostics: Workers
  export credential-free OTLP to an isolated Collector that injects
  cloud credentials; Workers never hold AgentLoop keys.
- Verified cloud acceptance: a disposable isolated run produced traces
  queryable through the read-only SLS channel, with spans carrying real
  `tiangong.work.id`/`tiangong.task.id` correlation.
- A fail-closed read-only trace query script is included for
  acceptance and demo use; repository-external credentials only.

## Known limitations

- The local delivery proof is disposable and local; production
  deployment, Git push, CI dispatch, and external writes remain closed
  until the staged Adapter/Operation milestones.
- Content capture is disabled by default and permitted only under an
  explicit `isolated-test` marker; hidden chain of thought is neither
  collected nor claimed.
- The `make specialist-handoff` contract references a removed test
  file and is not part of the active verification set.

This is a `v0.y.z` development release. Credentials remain
deployment-scoped and are never stored in source, images, receipts,
tool results, or logs.
