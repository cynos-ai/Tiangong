# Tiangong v0.4.0 release notes

Tiangong v0.4.0 is the DeepSeek-only OpenClaw-native clean-cut release on the
public AgentTeams v1.2.2 boundary.

## Included changes

- Removed the Tiangong-owned Pi runtime, harness adapter, session store, model
  gateway, patch-dependency script, Pi package, and legacy runtime fallback.
- Kept OpenClaw native control hooks/tools, RoleProfiles, Coordination, Gates,
  Evidence, approvals, ToolResult capture, and independent recovery state.
- Kept non-coding roles on the OpenClaw built-in runtime and routed Implementor
  coding through the official Codex app-server with fallback disabled.
- Pinned the current coding canary to DeepSeek native Responses/Codex. Qwen,
  Alibaba Coding Plan, and Chat-only bridge support remains a later opt-in
  canary and is not part of this release's green matrix.
- Updated Worker image, role injection, smoke contracts, observability names,
  documentation, and release gates to use the control/ToolResult vocabulary.

## Verification

- Focused clean-cut Worker tests: 24/24 passed.
- Migration gate, B5 role/runtime injection contract, Phase C deterministic
  boundary, image profile checks, repository policy, ShellCheck, DCO, Gitleaks,
  and Worker package CI passed.
- Full Windows `npm test`: 332 passed and 43 failed on known Windows-only
  fsync/symlink/deployment-fixture limitations; Linux CI is authoritative.
- Real DeepSeek Flash verification reached native Responses preflight, Codex
  app-server routing, Matrix handoff, ToolResult, and exact cleanup. Two fresh
  full Gate B reruns were blocked by external AgentTeams/WSL control-plane
  failures (STS/MinIO synchronization and a WSL vsock timeout); those runs are
  recorded as external verification limits, not product passes.

## Compatibility and limitations

AgentTeams owns Team, Worker, Matrix, storage, and WebUI lifecycle. Tiangong
owns the control plugin and professional role/evidence boundaries. AgentTeams
v1.2.2 still does not expose all Worker env/leader-session fields through its
`agt`/REST management surface, so production deployment must inject the
validated role and control bindings through the existing deployment layer.

Credentials remain deployment-scoped and are never stored in source, images,
receipts, ToolResults, or logs. This is a `v0.y.z` development release.
